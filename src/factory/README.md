# Optional Central factory

This module owns fixed factory stages and `factory.sqlite`. It does not import the native core. `src/core/factory.ts` adapts native tasks, conversations, execution IDs and receipts. Runner supplies four boundaries: execution binding, scoped tool dispatch, final provider input and observed completion. Native computer grants remain off; factory code calls the existing guarded offline worker with a current attempt/job/message fence.

The module is absent unless `DATA_DIR/factory/config.json` enables it. Deployment scripts, immutable pstack/Ponytail packaging, the JSON subset of `stages.yaml`, verification recipes, operator recovery and manual PR instructions live in Central's `infra/pilot/tucano/factory`. The controller accepts only the fixed compiled stage contract and pinned package. No workflow expressions, effect queue, alternate provider runtime or merge API exists.

One request key comes from the actual owner's message, not model arguments. Reservation precedes native task creation. An ambiguous crash remains blocked for operator reconciliation/cancellation; replay cannot create another task. Every model job uses a persisted native task request ID. Helpers return immediately and continue the build only after both native jobs finish. They share neither a CLI session nor write tools. A cancelled attempt cannot be reopened by a late completion; native receipts are still retained.

Startup hooks run for actual new executions. Only the first build receives the original human `UserPromptSubmit`; automatic continuations do not invent user events. Child runs inherit the parent's Ponytail level; Nina starts independently. The original hook scripts use the adapted Codex JSON protocol for either provider, file-backed stdin and a neutral environment. Hashes cover dependencies as well as entry points. Delivered system hashes are tied to the native message. No native plugin registration, resume event or compact event is claimed.

The fixed worker is prepared manually with only the current attempt writable. Baseline, candidate bundle, patch, verification and review evidence stay outside that mount. Build completion alone cannot close a task. Clean verification precedes manual publication; the exact candidate PR, required CI, independent Nina receipt validated by Central's existing checker and authorized human merge are mandatory. Failures retain the worker reservation until a trusted operator confirms drainage. Existing native tasks, linked issue identities and unrelated agent behavior stay on their native paths.

Run `npm run typecheck`, `npm run build` and the factory/Runner/task tests. `FACTORY_TEST_PACKAGE=/absolute/pinned/package npx vitest run test/factory-hooks.test.ts test/factory-runner.test.ts` additionally verifies original upstream hook bytes at both native provider boundaries with deterministic fake engines. Live model authentication, worker lifecycle and deployment evidence are separate rollout checks. Some local skill tests require unsetting an inherited `CODEX_HOME` so they use their fixture home.
